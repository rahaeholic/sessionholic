# 빈 창에서 세션 시작

목표: 분할로 만든 빈 창에서 새 세션을 시작하거나 기존 세션을 골라 해당 창에서 연다.

현재 동작: 분할은 null 세션 참조를 보관하므로 빈 창의 저장·복원과 드롭 대상은 이미 지원한다. 그러나 시작 화면은 안내문뿐이고 새 세션 버튼은 숨겨진 공통 목록에만 있다. 새 세션 기기 선택·중복 요청 방지·실행·터미널 연결은 기존 구현을 재사용한다.

수정 파일 및 순서:
1. `web/app.js`, `web/index.html`, `web/style.css`: 초기/분할 빈 창에 ‘새 세션’과 ‘기존 세션 열기’를 표시한다. 인증·기기 정보 로딩·오프라인 상태에 따라 새 세션 버튼 상태를 갱신한다. 주기적 조회에서는 같은 버튼 DOM과 포커스를 유지한다. 실행 중인 세션·터미널·봇 대화는 빈 창으로 덮지 않는다.
2. `web/workspace.js`: 빈 창 제목을 명시하고 기존 세션 목록을 여는 경로를 추가한다. 자식 창 소유권을 검사하고 해당 창을 활성화한 채 부모 목록을 연다. 새 세션은 클릭한 문서의 기존 기기 선택 창에서 열고, 창만 만들거나 새로고침하는 것으로 실행을 생성하지 않는다.
3. `tests/test_frontend.cjs`, `tests/test_workspace.cjs`: 시작 버튼 → 기기 선택(자동 실행 없음), 빈 창 복원, 자식 창 소유권, 목록 선택의 대상 유지, 기존 초안·터미널 문서 보존을 검증한다.
4. `README.md`, `scripts/public-files.json`: 조작 안내와 계획 파일을 등록한다. 서버·세션 실행 API·권한은 변경하지 않는다.

검증 순서: 관련 테스트와 전체 JS, 공개 파일 감사·diff 검사 → 기존 배포 절차의 격리 canary → 한 번의 운영 배포 → 제공 파일·기존 터미널·설정 보존 확인. 실제 브라우저 및 하드웨어 입력 검증은 승인된 개인 Chrome 연결이 있을 때만 수행한다.

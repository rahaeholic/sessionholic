# 첨부 32개와 터미널 붙여넣기

목표: 채팅·터미널에서 한 번에 파일 32개를 준비하고, 터미널 입력창과 터미널 화면의 파일 붙여넣기를 전송 전 미리보기로 처리한다.

확인된 원인: UI와 chat/native_chat/WindowsRuntime 및 초안 복구에 각각 8개 제한이 있다. terminal-draft는 텍스트·IME 이벤트만 연결돼 있고 파일 paste를 처리하지 않는다. 업로드는 이미 실제 세션의 작업 폴더를 확인하는 /api/chat/upload 경로가 있으므로 재사용한다.

순서와 파일:
1. `attachments.py`, `windows_attachments.py`, `chat.py`, `native_chat.py`, `windows_runtime.py`, `web/app.js`: 개수 32개, native 입력 블록/첨부 수신 증거/초안 복구의 관련 제한을 맞춘다. 파일당 기존 20MiB는 유지한다. Mac·PC에서 32개 전송/이력 확인과 33개 거부를 검증한다.
2. `web/app.js`, `web/index.html`, `web/style.css`: 터미널 ID별 첨부·업로드·미리보기·파일 선택·파일 paste를 연결한다. 실제 연결된 nativeSource만 대상에 사용하며, 연결 확인 중인 파일은 초안에 남겨 재시도할 수 있게 한다. 일반 텍스트 paste는 기존 동작을 유지한다.
3. 터미널 보내기/입력은 올린 파일 경로를 명시적으로 포함하며, 업로드 중에는 보내지 않는다. 전송 실패/결과 불명에는 초안과 첨부를 유지하고 자동 재전송하지 않는다. 탭/세션 이동 중 응답은 원래 터미널에만 반영한다. 초안 저장·로그아웃 시의 첨부/썸네일 정리도 연결한다.
4. 관련 Python/JS 회귀 테스트, 전체 테스트, 공개 파일 감사 후 기존 배포 절차로 한 번 배포한다. 운영 파일·터미널 보존 및 전달된 자산을 확인한다. 실제 사용자 세션에 테스트 파일/입력은 보내지 않는다.

삭제 파일 없음. 업로드와 native 전송은 인증·세션 식별·cwd 확인·수신 기록 검증을 그대로 사용한다. 첨부 파일 자체는 대화 보존 대상에 추가하지 않는다. 업로드에는 파일 저장만 수행하며 Enter/세션 실행을 자동 요청하지 않는다.

추가 버그: 실행 종료는 확인됐으나 `cleanup.unverified`에 추정 연결이 남으면 서버가 목록 정리를 영구 보류하고 종료 창의 같은 재시도가 반복된다. 확인된 실행과 실제 종료 대상 터미널 정리를 마치면 목록을 정리하고 창을 닫는다. 추정/변경/뒤늦게 열린 터미널은 종료하지 않고 결과 안내에 남긴다. 실제 terminal close/remote hold 오류에는 기존 결과 조회·정리만 재시도하는 경계를 유지한다. `server.py`, 종료 UI 및 HTTP/JS 회귀로 검증한다.

# 실제 종료 확인과 연결 정리 통합

목표: 사용자가 실행 종료를 선택하면 원본 종료를 확인한 뒤 정확히 연결된 보드 터미널·원격 hold·목록을 함께 정리하고, 일부 실패는 원본 종료를 반복하지 않고 재시도한다.

확인된 원인은 터미널 close가 모드만으로 원본 종료를 선언하고, native terminate는 터미널을 정리하지 않는 별도 경로라는 점이다. 추정 연결 close가 목록을 숨기는 회귀 테스트로 현재 오동작을 재현할 수 있다.

수정 파일:
- `terminal.py`, `server.py`: 연결 닫기와 원본 종료의 의미 분리. 종료 확인 이후 exact native identity·계정·작업 폴더·Claude sessionId에 해당하는 터미널만 닫는다. 추정 연결은 자동 종료하지 않는다. 원격 hold 확인 및 목록 제거는 단계별 결과로 반환한다.
- `session_control.py`, `transfer_worker.py`, `windows_runtime.py`: 기존 제어 영수증에 요청 시각·대상 바인딩을 보존하고, 재시도는 영수증 조회만 허용한다. 영수증 없는 요청을 실행으로 승격하지 않는다.
- `web/app.js`: 카드·키보드·관리 화면의 실행 종료를 같은 서버 처리로 연결한다. 연결만 닫은 결과를 실행 종료로 표시하지 않는다. 일부 정리는 버튼으로 재시도하며 탭 새로고침에도 요청 메타데이터를 유지한다.
- 관련 Python/JavaScript 테스트, `README.md`, `scripts/public-files.json`: 공개 문서와 회귀 검증.
- 참조만: `session_recovery.py`, 기존 배포 도구. 새 저장소·감시 서비스는 추가하지 않는다.

순서와 검증:
1. 잘못된 close→목록 숨김, native 종료 후 남은 터미널, 오프라인/실패를 합성 HTTP 테스트로 재현한다.
2. 종료 영수증 조회를 구현한다. `_observe`/`_apply` 미호출, 잘못된 ID·대상 거절, 재시작 뒤 조회를 검증한다.
3. 서버 종료·정리 통합. 미확인 결과는 후속 삭제 없음, exact 연결 여러 개 정리, 추정·다른 계정·폴더·대화 제외, 부분 실패 후 정리만 재시도를 검증한다.
4. UI 공통 처리·부분 실패·탭 복원 검증. 원본 제어 중복 클릭/자동 재시도 없음, 연결 닫기는 목록 변경 없음.
5. `python3 -m unittest discover -s tests -v`, `node --test tests/test_*.cjs`, `python3 scripts/check_public.py --release` 통과 후 한 번에 배포하고 설치 파일·헬스·기존 터미널 보존을 확인한다. 사용자 실행을 테스트 목적으로 종료하지 않는다.

범위 밖: 터미널 중심 화면 전환, 추정 연결을 exact로 승격, 사용자 음성/키보드 실기 검증. 실제 작업 종료는 선택한 원본의 제어 영수증으로만 판정한다.

추가 요청: 갤럭시의 창 이동 시 한글 조합 차단과 단일 화면 복귀를 수정한다. `compositionOwner`는 늦은 입력 대상 보존용 값이므로 조합 중 판정에서 제외하고 실제 포커스가 있는 입력창만 확인한다. 다른 창을 누르면 원래 입력창 blur 후 이동하며 초안·문서·음성 객체를 재생성하지 않는다. `web/workspace.js`, `web/index.html`, `web/workspace.css`에 명시적인 단일 화면/분할 복원 버튼을 추가하고 배치·초안 유지 및 새로고침 복원을 테스트한다.

정리할 터미널은 시간 비교로 고르지 않는다. 원본 종료 요청 전에 보드가 선택한 터미널 ID를 기존 native 영수증에 보존한다. 따라서 원격 기기 시계 차이 또는 종료 도중 새로 열린 같은 대화의 터미널은 정리 대상이 되지 않는다.

# 세션보드의 원이 대화

목표: 세션보드에서 원이의 기존 대화와 진행 상황을 확인하고 같은 원이에게 메시지를 보낸다.

파일 매핑:
- `woni_bridge.py` 신규: 명시적으로 설정된 기존 호스트를 통해 원이의 로컬 API를 호출한다. 인증값은 원이가 실행되는 기기에서만 읽는다.
- `server.py`: 기존 보드 인증 및 요청 검증을 거치는 제한된 원이 조회·전송 API를 연결한다.
- `web/index.html`, `web/app.js`, `web/style.css`: 원이 진입점, 기존 대화와 상태, 메시지 입력과 연결 오류를 표시한다.
- `tests/test_woni_bridge.py` 및 관련 프런트엔드 검증: 접근 범위, 중복 전송 방지, 오류 처리와 화면 흐름을 확인한다.
- `scripts/public-files.json`, `docs/limitations.md`: 필요한 공개 파일과 기능 범위를 반영한다.
- 원이 서버와 기존 대화 기록은 변경하지 않고 기존 `/v1/state`, `/v1/chat`, `/v1/activity` 계약을 사용한다.

순서와 검증:
1. 로컬 가짜 원이 서버로 허용된 API만 호출하고 비밀값을 노출하지 않는 브리지를 검증한다. 잘못된 설정·기기 중단·시간 초과는 명시적인 오류로 처리한다.
2. 보드 HTTP API에 브리지를 연결하고 인증·CSRF·본문 제한과 동일 요청 ID 재시도를 검증한다.
3. 기존 원이 대화, 처리 상태, 입력을 표시한다. 전송 결과가 불확실할 때 같은 요청 ID를 사용하고 새 작업을 중복 실행하지 않는지 확인한다.
4. 관련 Python 및 JavaScript 검사와 실제 연결·화면 확인을 수행한다. 운영 환경 연결 설정은 비공개 경로에만 두고 기존 데이터와 실행을 보존한다.

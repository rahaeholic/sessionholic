# 터미널·대화 연결과 종료 관리

목표: 확정 근거가 있는 세션 연결은 추정 오류에서 복구하고, 서버 재시작이 미사용 정리를 무기한 미루지 않게 한다. 연결을 모르는 실행을 임의로 종료하거나 다른 대화와 묶지 않는다.

확인된 사실:
- 운영 시점의 살아 있는 터미널은 16개다. 목록상 작업 중 2개, 대기 7개, 목록과 세션을 대조하지 못한 7개다. 시간 기반 추정으로만 연결된 터미널도 있어 ‘목록에 있음’과 ‘같은 실행으로 확정됨’은 다르다.
- terminal.py의 link_native는 뒤늦게 얻은 정확한 세션이 기존 추정과 다르면 거부한다. 잘못된 추정이 영구 고정될 수 있다.
- 미사용 시간은 메모리의 monotonic touched만 쓰고 재시작마다 초기화된다. 실행 터미널의 기준은 3시간이므로 그보다 잦은 재배포는 정리를 계속 미룬다.
- 운영의 추정 Codex 세 개는 현재 CLI/하위 프로세스가 jsonl을 열고 있지 않다. held_codex의 writable rollout 탐색은 모두 실패했다. 따라서 아래 수정만으로 이 세 개의 신원을 복구했다고 주장할 수 없다.
- Codex 공유 daemon에서 TUI가 표시하는 대화를 클라이언트별로 알아내는 제약은 upstream #48880/#48500에서도 확인된다. 시간·작업 폴더·최근 사용만으로 다른 대화를 확정하거나 공유 서버를 중지하는 방법은 쓰지 않는다.

구현 순서:
1. tests/test_terminal.py: 잘못된 추정이 서버가 발견한 같은 기기의 정확한 신원으로 교정되는 회귀 실패를 만든다. 확정된 연결·호스트 경계·저장 실패 롤백은 유지한다. terminal.py link_native를 수정한다.
2. tests/test_terminal.py: 마지막 실제 사용 시각이 저장·재시작 후 유지되고, 복구 유예 중에는 자동 종료 후보가 아니며, 새 입력/조회는 다시 사용 중으로 만드는 것을 검증한다. terminal.py의 _Terminal/_load/_save/_use 및 idle 후보 판정에 저장 시각과 복구 유예를 적용한다. 입력/화면 조회마다 디스크를 쓰지 않도록 저장을 제한하고 종료 시 마지막 사용을 기록한다. 기록 없는 옛 항목은 첫 적용 시점부터 시작하며 실행 종료를 추정하지 않는다.
3. 사용자가 보고한 채팅 열기 실패는 실제 제목을 받아 nativeSource와 대조한다. 확인되지 않은 Codex TUI 신원은 별도 남은 문제로 보고한다. 새 native 생성 흐름·외부 CLI 전역 설정·공유 daemon 종료는 이번 작은 수정의 범위에 넣지 않는다.
4. README/limitations/공개 허용 목록을 갱신하고 변경 관련 Python, 전체 JS, 공개 감사를 수행한다. 격리 canary 후 배포 한 번과 파일·설정·기존 터미널 보존을 확인한다. 실제 사용자 세션을 테스트용으로 종료하지 않는다.

검증: 관련 fixture는 원래 실패 → 변경 후 통과를 기록한다. 미사용 시간 저장 빈도, 재연결 유예, 오래된 기록 마이그레이션, 교정 시 기존 첨부/대화의 신원 경계가 유지되는지를 검토한다. 전체 native 연결 회복과 자동 정리 완료를 단순 배포 성공과 혼동하지 않는다.

참고: https://github.com/openai/codex/issues/48880 · https://github.com/openai/codex/issues/48500

저장 경계: 기존 sessions.json의 신원·소켓·종료 트랜잭션을 바꾸지 않고 같은 개인 상태 폴더의 activity.json에 불투명 터미널 ID와 마지막 사용 시각만 저장한다. 30초 동안 반복되는 화면 조회는 묶어서 저장하되, 오래 쉬던 연결의 첫 사용은 즉시 기록한다. 복구 후 5분은 자동 종료에서 보호한다. 연결 신원 없는 과거 터미널을 새로 죽이는 정책은 추가하지 않는다.

사용 기록 파일이 손상되거나 링크일 때는 원본을 읽어 따라가거나 덮어쓰지 않고, 현재 시작 시점부터 보수적으로 사용 시간을 센다. 선택적 정리 기록 때문에 실제 터미널·보드 기동을 막지 않는다. 신원/제어 영수증의 엄격한 검증은 유지한다.

사용자가 Codex 질문 보기용 Shift+왼쪽 화살표 버튼도 요청했다. 같은 배포에 web/app.js의 preset(ESC[1;2D), web/index.html의 ⇧← 버튼, web/style.css의 기존 빈 키 칸 배치를 추가한다. tests/test_frontend.cjs로 정확히 한 번의 전송과 Ctrl 병합 시 ESC[1;6D 및 modifier 해제를 검증한다. 이 버튼을 테스트하기 위해 실제 작업 터미널에 키를 보내지 않는다.

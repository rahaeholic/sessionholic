# 세션 드롭 분할 수정

목표: 목록의 다른 세션을 사용 중인 창에 놓으면 실제로 두 창이 생기고, 드롭 안내와 실행 결과가 일치한다.

확인한 원인: `workspace.js`의 `drop()`은 가운데 드롭을 기존 창의 `select()`로 처리한다. 이미 해당 창에 열린 세션은 `move()`의 같은 대상 거부로 아무 변화 없이 끝나며, `cue()`는 이를 구별하지 않는다. 준비되지 않은 빈 자식 창 가운데 드롭도 선택 함수를 호출하지 못한 채 끝난다. 승인된 Chrome 연결은 현재 도구 인증 실패로 실제 화면 조작이 불가능하므로 합성 이벤트 검증과 실기 확인을 구분한다.

변경 파일:

- `web/workspace.js`: 드롭 의도를 안내와 실행에서 공유한다. 사용 중인 창의 가운데에는 다른 세션을 오른쪽 분할로 연다. 빈 창 가운데는 해당 창을 채우며, 준비 중이면 참조를 보관한다. 이미 같은 창에 열린 세션은 이유를 알린다. 다른 창에 이미 열린 세션의 이동/교환과 최대 4개 제한은 유지한다.
- `tests/test_workspace.cjs`: 실제 등록된 dragstart/dragover/drop 핸들러로 안내와 창 개수·원래 대화 유지·준비 중인 창·동일 세션·최대 개수를 검증한다.
- `README.md`: 가운데 드롭의 동작을 설명한다.
- `web/index.html`, `web/workspace.css`: 드래그 중에만 부모 문서의 투명한 드롭 표면을 제공해 iframe 위에서도 부모가 드롭을 받는다. 실제 브라우저 이벤트 전달 장애의 원인으로 확정한 것은 아니며, 무반응 경로의 호환성 보강이다. `workspace.js`는 캡처 단계에서 드롭을 받고 허용 동작을 명시한다.

참조만: `web/app.js`의 카드 및 세션 선택, `web/workspace.css`의 좌표 배치, 이전 배포의 불변 소스/검증 도구. 터미널 실행과 로그인 정보는 변경하지 않는다.

구현 순서:

1. 사용 중인 창 가운데 드롭 회귀 테스트로 기존 코드의 실패를 확인한다.
2. 공유 드롭 의도와 빈 창 보류 처리를 구현하고 관련 회귀 테스트를 통과시킨다.
3. 전체 JavaScript 검사와 공개 파일 감사, 변경 diff를 확인한다. Python 실행 경로는 변경하지 않는다.
4. 기존 운영 해시 확인, 별도 canary, 한 번 배포 후 파일/응답 및 살아 있는 터미널 보존을 확인한다. 실제 브라우저 조작 여부와 사용자의 재확인 필요를 명시한다.

별도 조사 범위: 목록에서 지운 세션의 자동 터미널 종료는 아직 구현하지 않는다. 명시적 제거 기록을 기준으로 확인된 보드 소유 연결만 정리하고, 필터·수집 실패·추정 연결을 종료 근거로 사용하지 않는 방안을 보고한다.

## 후속 요청: 반복되는 요청 오류 표시

실제 최근 세션을 입력 없이 조회한 결과, 실패한 세 번의 응답은 Native의 `serverOverloaded`였으며 이후 응답이 계속됐다. 후속 turn이 있는 실패 수신 기록 여섯 건도 확인했다. `receiptNotice()`는 완료/중단된 이전 요청만 새 작업 중에 숨기고 실패한 요청은 계속 보여주며, `.is-error` 역시 무조건 실패 상태로 칠한다. 상위 응답 서버의 혼잡과 보드의 오래된 오류 표시를 구분한다.

추가 변경 파일/순서:

1. `tests/test_frontend.cjs`: 후속 turn이 증명된 이전 실패는 문구와 오류 장식에서 해제하고, 현재 실패·전송 거절·실행 중이라는 사실만 확인한 경우는 유지하는 회귀 테스트를 먼저 실패시킨다.
2. `web/app.js`: 같은 대화의 최신 조회에서 기존 실패 turn보다 뒤의 turn이 확인됐을 때만 표시를 해제한다. 한 번 확인한 후속 진행은 조회 창에서 과거 turn이 빠져도 기억한다. 수신/실패 기록 자체와 입력·재전송 정책은 유지한다.
3. `native_chat.py`, `chat.py`: 확인된 실패의 `serverOverloaded`만 공개된 `server_overloaded` 코드로 전달한다. Native 오류 원문은 전달하지 않는다. 현재 실패는 원인을 구체적으로 안내한다.
4. `tests/test_native_chat.py`, `tests/test_chat.py`: 오류 코드 전달과 임의 문자열 배제, 실패 수신 사실 유지, 읽기 전용 조회를 검증한다.
5. 전체 JavaScript/Python 테스트 및 공개 파일 감사 후 분할 수정과 한 번에 배포한다. 실제 서버 혼잡 자체를 해결했다고 보고하지 않는다.

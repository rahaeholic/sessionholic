# 입력창과 분할창 메뉴 개선

목표: 좁은 분할창에서도 입력칸은 전체 가로폭을 확보하고, 앱 공통 메뉴와 창별 조작을 분명하게 구분한다.

확인한 원인: `.chat-main`의 한 줄 flex 안에 고정 너비 버튼 네 개와 textarea가 있어 280~320px 창에서 입력칸이 남은 수십 px로 줄어든다. 집중모드에서 추가되는 첨부·빠른 답장 버튼 때문에 더 심해진다. 상단에는 기기 관리·창 번호·확대·분할 추가가 함께 있고, 각 창 헤더에도 분할·확대 버튼이 중복된다.

변경 파일과 순서:
1. `web/style.css`, `web/app.js`: 입력칸을 첫 줄 전체 폭으로, 첨부·음성·빠른 답장과 보내기를 다음 줄에 배치한다. 기존 입력 DOM·이벤트·전송 경로는 유지하고, 일반/집중모드 모두 같은 주요 버튼을 사용한다. 일반모드 부가 도구는 기존 도구 줄에 남긴다.
2. `web/index.html`, `web/workspace.css`, `web/workspace.js`: 공통 상단 왼쪽은 브랜드·기기, 오른쪽은 새로고침·설정·분할 추가. 중복된 전역 확대 버튼을 제거한다. 각 창에는 번호·제목·기기 경로와 이 창 확대/분할로 돌아가기·닫기만 둔다. 좁아서 한 창씩 보이는 경우에만 상단 번호 전환을 표시한다. Option+숫자는 계속 지원한다.
3. `tests/test_frontend.cjs`, `tests/test_workspace.cjs`: 작성 중 DOM·조합·음성·첨부 동작 유지, 창별 확대/복원의 원래 문서·초안 보존과 좁은 화면 전환을 검증한다. 이전 마크업에 묶인 기대값은 새 역할에 맞춘다.
4. `README.md`, `docs/limitations.md`, `scripts/public-files.json`: 변경한 조작 방식과 실제 브라우저 검증 한계를 기록한다.

검증: 관련 JS와 전체 JS 테스트, 공개 파일 감사와 diff 검사를 통과시킨 뒤 격리 canary와 한 번의 배포를 진행한다. 배포 후 제공 파일 해시·기존 터미널·설정을 확인한다. 현재 승인된 Chrome 연결 목록은 비어 있으므로 픽셀 배치·실제 키보드/마이크 입력 확인은 자동 테스트와 별개로 미검증으로 보고한다. 다른 프로필이나 브라우저로 우회하지 않는다.

서버·터미널 전송·세션 종료·권한은 수정하지 않는다. 창 조작은 기존 문서를 교체하거나 터미널을 종료하지 않는다.

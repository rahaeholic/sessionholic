# 세션 화면 분할

목표: 기존 채팅/터미널 탭과 입력을 보존하면서 최대 네 세션을 드래그로 배치하고 Mac·iPad 외장 키보드로 창을 이동한다.

## 변경 파일

- `web/workspace.js` 신설: 배치 트리, 창 수명/초점, 드래그와 경계 조절, 확대, 세션 참조만 저장, 동일 터미널 중복 방지, 같은 출처 자식 창의 공통 조회 공유.
- `web/workspace.css` 신설: 단일 화면 유지, 활성 창과 도구막대, 분할 경계와 드롭 표시, 작은 화면의 활성 창 보기.
- `web/index.html`: 기존 상세 DOM을 유지하는 창 컨테이너, 분할 도구와 정적 파일 로드.
- `web/app.js`: 창 컨트롤러 연결, 세션 선택/새 세션의 활성 창 라우팅, 공통 데이터 조회 공유, 잠금 전파, 분할 단축키를 터미널 입력보다 먼저 처리.
- `server.py`: `/pane`에만 같은 출처 프레임 허용. 기존 페이지/API의 프레임 차단은 유지.
- `web/sw.js`: 새 공개 정적 파일만 캐시에 포함. 창 참조·대화·API는 캐시하지 않음.
- `tests/test_workspace.cjs`, `tests/test_server.py` 및 관련 기존 프런트엔드 테스트: 배치·입력 대상·수명·보안 경계 검증.
- `tests/test_instance.py`, `scripts/public-files.json`: 새 공개 정적 파일 허용 목록과 서비스 워커 캐시 버전 검증.
- `README.md`: 사용법과 Mac/iPad 단축키.

참조만: `terminal.py` 실제 실행/연결 수명, `events.py` 기존 공유 감시, 이전 배포의 개인 빌더/검증 스크립트. 기기·계정·native 세션 및 호스트 설정은 변경하지 않는다.

## 구현 순서와 기대 결과

1. 순수 배치 모델: 최대 네 창의 이진 분할, 이동/교환, 제거, 비율 제한, 방향 탐색과 저장 데이터 검증. Node 테스트에서 중복/유실/잘못된 저장값을 거부한다.
2. 창 격리: 기존 첫 창의 DOM은 그대로 두고 추가 창은 같은 출처의 독립 문서로 관리한다. 창 이동은 좌표만 변경하며 프레임을 재삽입하지 않는다. 공통 snapshot/capabilities/terminal 목록은 상위 창에서 공유하고 자식은 별도 전역 SSE를 만들지 않는다.
3. 조작: 목록 드래그로 새 창, 창 제목 드래그로 재배치, 경계 조절, 분할 버튼, 닫기, 확대/복원. 닫기는 실행 종료 API를 호출하지 않고 미완료 전송/입력을 보호한다. 동일 세션/터미널은 기존 창으로 이동한다.
4. 키보드/모바일: Control+Command+방향키/1~4/Enter. 기존 Option+왼쪽은 유지한다. 채팅·터미널 양쪽에서 창 단축키가 CLI로 유출되지 않게 하고 조합 중 입력과 음성 대상을 보존한다. 좁은 화면은 같은 배치에서 활성 창만 표시한다.
5. 검증: `node --test tests/test_*.cjs`, `python3 -m unittest discover -s tests`, `python3 scripts/check_public.py`. 경계/단축키/복원/잠금/조회 공유 회귀 테스트와 허용된 Chrome 연결로 가능한 범위의 합성 UI 검증. iPad 실기 키 조합·마이크 검증 여부를 구분해 기록한다.
6. 배포: 변경 집합·현재 운영 파일 해시 확인 → 별도 canary → 불변 커밋에서 한 번 배포/필요 시 보드만 한 번 재시작 → 운영 파일/응답 해시와 기존 터미널 생존 확인. 기존 24시간 관찰은 계속 유지한다.

## 검토 기준

- 기본 화면·계정 매칭·승인·입력 전송은 기존 경로를 재사용한다.
- 창 배치를 바꾸는 동작은 native 실행 생성/재개/종료를 하지 않는다.
- 저장값은 세션 키/터미널 ID와 배치 비율만 포함하며 초안·대화·인증은 포함하지 않는다.
- 인증 해제는 모든 창의 데이터·음성·입력을 동시에 해제한다.

## 작업 중 추가 확인한 터미널 문제

- 실행 중인 Codex 터미널이 추정 연결로만 남는 경우가 있다. 대화 파일을 직접 쓰지 않는 클라이언트 실행 방식에서는 기존 파일 기반 확인으로 정확한 연결을 증명하지 못한다. 추정을 정확한 연결로 승격하지 않는다.
- 목록의 첫 추정 터미널이 뒤에 있는 확인된 연결보다 먼저 선택되는 프런트엔드 문제를 수정한다. 같은 native ID·계정·cwd로 확인된 연결을 우선 사용한다.
- 추정 연결만 있으면 오류로 막는 대신 기존 대화의 동일 기기·계정·ID에 연결하는 검토 화면으로 이어 준다. 화면 동작 자체는 새 대화를 만들거나 native 입력을 보내지 않는다.
- 새 실행기가 실제 로그인 계정과 선택 계정의 불일치로 종료하는 경우에는 원인을 표시하고 계정을 다시 선택할 수 있게 한다. 계정 확인과 로그인 상태는 유지한다.
- 추가 검증: 확인된 연결 우선순위, 잘못된 cwd 배제, 추정 연결의 동일 대화 검토 경로, 초안 보존, 실행기 오류 줄바꿈과 종료 후 메뉴 해제 회귀 테스트.

# 채팅 전송으로 같은 세션 연결

목표: 끊긴 세션의 채팅에서 보내기를 누르면 같은 기기·계정·대화에 연결한 뒤, 누른 순간의 메시지와 첨부를 한 번만 보낸다.

파일 매핑:
- 수정: `chat.py`, `server.py` — 기존 plan/launch를 재사용하는 메시지 없는 연결 API와 준비 확인. 연결 가능한 Windows Claude의 전송 경계도 처리한다.
- 수정: `web/app.js` — 연결 가능한 상태에서 보내기 허용, 연결 중/전송 중 표시, 동일 요청과 초안 보존. 화면 이동 없이 기존 전송 경로로 이어진다.
- 수정: `tests/test_chat.py`, `tests/test_frontend.cjs` — 같은 원본 연결, 준비 전 입력 금지, 중복 클릭, 실패·응답 유실·대화 전환·로그아웃·첨부 보존 회귀.
- 수정: `docs/limitations.md`, `scripts/public-files.json` — 동작과 이 계획 등록. 추가 파일은 이 계획뿐이며 삭제·새 의존성은 없다.
- 참조: `launch.py`, `native_chat.py`, 기존 세션 종료·전송 영수증·터미널 관리. 원격 helper와 계정 설정은 변경하지 않는다.

순서와 검증:
1. 기존 지원 여부와 복구 판단을 구분해 연결할 수 있는 채팅의 보내기를 활성화한다. 읽기·타이핑만으로 종료된 프로세스를 시작하지 않는다.
2. 연결 요청은 본문을 받지 않고 같은 원본의 기존 실행 계획과 준비 확인만 수행한다. 서버가 거부한 종료·보관·외부 전용 세션은 그대로 거부한다. 합성 서버 테스트에서 native 입력 0회와 정확한 계정을 확인한다.
3. 보내기에서 메시지·첨부·원본·요청 ID를 고정하고 연결 성공 후 기존 send를 한 번 호출한다. 실패는 미전송으로 처리하며 전송 후 응답 유실은 기존 결과 미확인 규칙을 유지한다. 다음 초안과 다른 세션에 영향을 주지 않는지 frontend fixture로 검증한다.
4. 관련 회귀 후 전체 Node/Python 검사, 공개 파일 검사와 diff 검사를 실행한다. 최신 운영 트리를 보존한 Mini 카나리·사전 검사·배포·실제 제공 파일 확인을 수행한다. 운영 대화에 시험 지시는 보내지 않는다.

검토: 연결 API는 임의 계정·새 대화·인계 옵션을 받지 않는다. 사용자 종료에 대한 기존 재개 정책과 승인 메뉴를 우회하지 않는다. 운영 chat.py의 기존 수정은 덮어쓰지 않고 해당 기준 파일에 패치를 적용한다.

# 원이 팝업 대화 입력 개선

목표: 세션보드 원이 팝업에서 기존 대화 흐름을 읽고, 키보드·파일·음성으로 편하게 질문한다.

원인: 팝업은 전송 버튼에만 연결된 독립 폼이며 기존 보드의 키보드·음성 및 원이 첨부 API를 사용하지 않는다. 원이 서버는 파일 10개·개당 100MB 첨부와 기존 대화 기록을 지원한다.

디자인: 세션보드의 중립 표면·대화 말풍선·절제된 파란 보내기 버튼을 재사용하고 입력과 첨부 상태를 한 영역에 모은다. 모바일 안전 영역과 팝업 내부 스크롤을 유지한다.

파일과 순서:
1. `woni_bridge.py`, `server.py`: 인증·CSRF 뒤에 크기 제한과 중단 처리가 있는 바이너리 업로드를 추가하고 원이 API의 첨부 ID를 그대로 연결한다. 기존 요청 ID의 재시도와 첨부 일치 검증을 보존한다. 원격 전송은 SSH 표준 입력을 쓰고 인증값은 원이 기기에서만 읽는다.
2. `web/index.html`, `web/woni.js`, `web/app.js`, `web/style.css`: Cmd/Ctrl+Enter와 한글 조합 보호, 파일 선택·붙여넣기·제거·상태, 기존 보드 음성 받아쓰기, 읽기 좋은 대화와 반응형 팝업을 제공한다. 전송 대기 중 초안과 첨부를 보존한다.
3. `tests/test_woni_bridge.py`, `tests/test_woni_http.py`, `tests/test_woni_frontend.cjs`: 유효하지 않은 첨부·크기·인증 거부, 전송 ID 보존, 키보드와 한글 조합, 파일 업로드 실패 및 음성 연결을 합성 환경에서 검증한다.
4. `docs/limitations.md`, `scripts/public-files.json`: 실제 지원·제약 및 파일 목록을 갱신한다. 기존 원이 서버와 사용자 대화에는 시험 메시지·파일을 보내지 않는다.
5. 관련 자동 검사와 sloplint를 수행하고 개인 Chrome에서 실제 화면을 확인한다. 검증된 변경을 격리 보드에서 확인한 뒤 기존 운영 파일과 실행 중 터미널을 보존해 배포한다.

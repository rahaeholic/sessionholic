# CLI 자동 갱신과 봇 최신 목록

목표: 머신마다 기존 세션을 유지하며 Codex를 주기적으로 갱신하고 Claude의 갱신 상태를 확인한다. 보드에서 버전·최근 결과를 확인하고 봇 요청은 최신 항목이 먼저 들어오는 제한 목록으로 유지한다.

현재 확인: Mac 3대 Codex는 npm, Windows는 standalone이다. Claude는 전부 native 자동 갱신이 켜져 있고 Windows는 stable, Mac은 latest다. 기존 git-auto-update는 저장소 갱신이며 CLI 패키지를 갱신하지 않는다. 이번 작업은 해당 업무 저장소나 인증을 수정하지 않는다.

파일 매핑:
- `bot_requests.py`, `web/app.js`, 관련 봇 테스트: 200개 제한 전 선택·정렬·갱신 경로를 조사하고 최신 우선으로 수정한다.
- 새 `cli_maintenance.py`: 표준 라이브러리 기반 머신별 실행 파일 확인, Codex 업데이트, Claude 진단, 중복 실행 잠금, 원자적 상태 기록, read-only 상태 출력. scheduler가 쓰고 웹 요청은 상태만 읽는다.
- 새 `cli_monitor.py`, `server.py`: 기존 등록 호스트의 read-only 상태 수집, 백그라운드 캐시·오프라인 표시, 인증된 조회 API. 모니터 전용 MacBook Pro도 포함한다.
- `web/index.html`, `web/app.js`, `web/style.css`: 설정에서 설치 버전·자동 갱신 상태·최근 결과 표시. 새로고침은 갱신 프로그램을 실행하지 않는다.
- 새/기존 tests, `scripts/public-files.json`, `README.md`: 동작 검증·공개 파일 목록.
- 배포용 머신 설정·스케줄·실행 기록: 비공개 `~/.codex-personal/discussions/` 및 각 머신 사용자 상태 폴더. 인증·대화·업무 지침은 복사하지 않는다.

순서:
1. 봇 목록 제한/정렬을 실제 read-only 증거와 테스트로 재현하고 수정한다. 오래된 요청 200개 뒤에 추가된 요청이 표시되는지 검증한다.
2. updater를 합성 경계 테스트로 검증한다. npm은 별도 버전 폴더에 준비하고 검증한 실행 경로만 원자 전환하여 기존 npm 파일과 실행을 보존한다. Windows는 기존 standalone 갱신 명령을 사용한다. 기존 세션·daemon을 중지하지 않는다. Claude는 기존 채널·자동 갱신을 유지하고 결과를 읽는다.
3. Mac LaunchAgent/Windows 사용자 예약 작업을 설치한다. 부팅/로그인 뒤 및 하루 단위로 실행하고 실패를 기록한다. 최초 실행과 등록 상태·다음 실행을 확인한다.
4. 보드 캐시/API/UI를 연결한다. 오프라인 기기·오래된 확인·일부 실패를 구분하고 새로고침이 설치/업데이트/세션 실행을 하지 않는지 검증한다.
5. 전체 Python/JavaScript 회귀 및 공개 감사 후 한 번 배포한다. 기존 터미널 보존, 제공 자산 해시, 실제 머신 상태 API와 최신 봇 요청을 read-only로 확인한다.

검증 경계: 업무 봇 ledger는 기존 보드의 읽기 경로만 사용한다. 실제 요청을 생성·전송하거나 사용자 작업을 종료하지 않는다. 설치된 버전과 살아 있는 daemon 버전이 다를 수 있으므로 새 바이너리를 설치했다고 기존 실행도 갱신됐다고 표시하지 않는다.

추가 요청: 모바일 종료 바텀시트의 데스크톱 width 규칙이 공통 모바일 width를 덮는 문제를 공통 선택자의 우선순위로 수정한다. 다른 바텀시트도 모바일에서는 좌우 폭을 채운다. Claude가 사용되지 않는 날에도 갱신되도록 기존 native `update`를 예약 실행하고 stable/latest 채널은 유지한다.

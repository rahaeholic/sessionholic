# Mac 터미널 한글 입력과 보기 전환 키

목표: 하던일 앱의 검은 터미널에서 빠른 한글 조합이 누락되는 경로를 고치고 Option+0으로 현재 창의 터미널/채팅 보기를 전환한다.

구분한 근거:
- 사용자 확인: Mac 하던일 앱의 터미널 직접 입력에서 모음을 두 번 눌러야 한다. 아래 작성창·iPad·갤럭시에서의 동일 증상은 확인하지 않았다.
- 확인된 결함: 배포 중인 xterm 6.0.0의 실제 CompositionHelper를 격리 VM에서 재생하면, 연속 조합의 지연 콜백과 다음 키가 겹칠 때 ‘니다’가 ‘니’로 누락된다. 비동기 전송을 공통 boolean 하나로 취소하고, 지연된 end offset만 사용하는 코드가 원인이다. 실제 키보드 재현과 이 fixture 재현을 구분한다.
- 현재 운영 tmux의 client_utf8는 1이다. UTF-8 설정 누락이 지금 증상의 원인이라는 증거는 없다. 상류 이슈 #6084는 작성자가 철회했으므로 그 글의 사용자 정의 WebKit 입력 브리지는 채택하지 않는다.
- 사용자가 말한 모든 모음 누락이 이 경쟁 조건 때문인지는 실제 앱에서 아직 검증하지 못했다. 승인된 Chrome 연결은 비어 있다.

순서와 파일:
1. 새 `web/terminal-ime.js`: 핀된 xterm 6.0.0의 조합 확정 처리만 보정한다. 읽기 가능한 작은 호환 모듈로 지연 전송을 순서대로 처리하고 이미 보낸 범위를 중복 전송하지 않는다. 원래 조합 이벤트·후보 표시·키 처리·붙여넣기는 유지한다. private helper 모양을 검사하며 재설치/화면 reset/폐기 시 늦은 콜백의 잘못된 전송을 막는다. vendor 번들을 직접 편집하지 않는다.
2. `web/app.js`: xterm 생성 시 보정 설치, onData를 생성 당시 terminal/인스턴스에 묶는다. raw IME 조합도 감지하고, 보기 전환은 같은 작성창의 조합을 마친 뒤 수행한다. 첨부·초안·마이크·실행을 보존한다.
3. `web/workspace.js`: Option+0을 window capture에서 현재 창의 보기 전환으로 연결한다. 단일 창과 분할 모두 지원하며 열린 대화상자·빈 창·읽기 전용 기록에서는 처리하지 않는다. Option+1~4 창 선택·방향키·CLI 일반 입력은 유지한다.
4. `web/index.html`, `web/sw.js`: 새 모듈을 버전 자산으로 제공하고 단축키 안내를 추가한다.
5. 새 `tests/test_terminal_ime.cjs`, 기존 frontend/workspace 테스트: 실제 번들의 조합 helper로 누락/중복·받침 이동·Enter 순서·폐기 경계를 검증한다. 실제 native 실행·모델 입력은 하지 않는다. 보기 전환은 원래 입력 DOM·초안·음성 유지와 활성 창 소유권을 확인한다.
6. `README.md`, `docs/limitations.md`, `scripts/public-files.json`: 지원 키와 실기 검증 한계를 기록한다.

검증: 보정 전 실제 vendor 재생 실패 → 보정 후 회귀 및 전체 JS·공개 감사 → 격리 canary → 한 번 배포 → 파일·기존 터미널·설정 보존 확인. 실제 Mac 하드웨어와 모바일 검증은 별도로 미확인이라고 보고한다.

참고: https://github.com/xtermjs/xterm.js/issues/6089 · https://github.com/xtermjs/xterm.js/pull/6090 · 철회된 보고 https://github.com/xtermjs/xterm.js/issues/6084

## 같은 배포에 추가된 사용자 보고

- 종료 반복: 운영의 미확인 Codex 요청을 읽기 전용으로 확인했다. 실행은 closed·safe이고 loaded 목록에도 없지만 archived=false였다. 기존 receipt()는 저장된 unconfirmed를 그대로 반환하므로 재확인으로 끝낼 방법이 없었다. session_control.py의 receipt/_reconcile은 원래 요청의 대상과 신원을 확인한 뒤 실행 상태만 재조회한다. 이미 끝난 Codex는 별도 종료·보관 명령 없이 정리하고, 보관 여부와 실행 종료 여부를 구분한다. 새 CLI 신호 전에는 부모와 자식 프로세스의 시작 시각·신원을 저장한다. tests/test_session_control.py 및 HTTP 경계 테스트로 재시작·옛 기록·다시 실행 중인 세션·타 계정/경로·응답 유실·정리 완료를 확인한다. 실제 사용자 세션 종료로 테스트하지 않는다.
- 네 창이 한 창처럼 표시됨: 연속 오른쪽 분할은 1/2·1/4·1/8·1/8 너비가 되고, 기존 workspace.layout은 좁은 leaf 하나만 있어도 전체를 compact로 전환했다. 먼저 2×2 등 균등 배치를 시도하고, 문서·초안을 유지하는 ‘분할 정렬/분할로 돌아가기’를 상단에 제공한다. 진짜 작은 화면의 창 선택은 유지하며 ‘창 1…4’로 표시한다. workspace 모델/DOM fixture로 네 창 표시·복원·한 창 확대 복귀·실행 비호출을 검증한다.
- 터미널 보기의 선택 전달 상태 상자는 CSS로 숨긴다. 채팅 보기의 선택 UI·기존 전달 영수증·중복 방지는 보존한다. 키보드 영역에 ⌃↑ 버튼을 추가하고 기존 sendInput 경로로 ESC[1;5A를 한 번 전달한다. tests/test_frontend.cjs에서 정확한 바이트와 기존 키 배치를 검증한다.

## 후속 수정: 사용자가 정한 배치 보존

사용자가 자동 4분면 변경을 지적했다. 앞선 narrow-leaf 보정은 layout()에서 트리를 직접 tiled()로 덮어쓰고 저장하여 분할 의도를 잃게 했다. ‘연속 오른쪽 분할·저장 배치 복원·창 크기 변경에도 방향과 비율이 유지된다’는 회귀 테스트 두 개가 기존 코드에서 실패하는 것을 확인했다.

web/workspace.js의 layout()에서 자동 tiled 및 leaf 크기 기준 compact 전환을 제거한다. 모바일 탭 표시는 viewport 너비로만 정하고 데스크톱의 좁은 창도 계속 표시한다. 균등 배치는 명시적 arrange()에서만 수행하며, 그때도 문서·초안·실행을 보존한다. 이전 버전이 이미 덮어쓴 배치는 원래 모양을 추정해 강제로 바꾸지 않는다. tests/test_workspace.cjs로 저장 트리 보존, 모바일 왕복, 직접 정렬·확대 복귀를 검사하고 전체 JS 및 공개 감사 후 한 번 배포한다.

사용자는 4분면을 쓰지 않고 세로형 창을 선호한다고 명시했다. 명시적 정렬도 2×2를 만들지 않고 항상 높이 전체를 사용하는 열을 좌우에 배치한다. 2·3·4개 모두 같은 너비를 갖도록 중간 분기의 ratio를 창 개수에 맞춘다. UI 이름은 ‘세로 정렬’이며, 확대 중의 ‘분할로 돌아가기’는 tiled()를 부르지 않고 원래 배치로만 복귀한다. 회귀 테스트에서 기존 정렬의 세로 공간 분할 및 복귀 시 트리 변경 실패를 확인한 뒤 고친다. 새 실행·입력·프레임 재생성 없이 정렬하는 것을 검증한다.

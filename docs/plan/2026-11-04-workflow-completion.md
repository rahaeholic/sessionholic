# 남은 세션보드 워크플로와 코드 보관

목표: Claude의 원본 대화를 안전하게 분기하고, 기기·작업 폴더·모델·에포트 프로필로 새 세션을 열며, 검토한 다중 대화 실행을 브라우저 종료 후에도 서버에서 안전하게 진행한다. 완료 후 개인 GitHub에 각 프로젝트의 검증된 변경을 보관한다.

1. Claude 분기: `chat.py`, `launch.py`, `transfer.py` 및 원격 Windows 경로와 UI를 실제 CLI 지원 범위에 맞춰 연결한다. 원본 세션·계정·작업 폴더를 검증하고 새 분기와 원본을 구별하며 요청 재시도 시 중복 실행하지 않는다. 가짜 CLI/임시 계정으로 정상·실패·불명·중복 요청을 테스트한다. 권한 설정을 자동으로 완화하지 않는다.
2. 새 세션 프로필: 기존 프로필과 런처·계정/프로젝트 설정을 조사한 뒤 선택한 기기·에이전트·작업 폴더·모델·에포트가 실제 생성 세션에 적용되는 경로를 구현한다. 운영 중 CLI 설정과 승인 정책은 보존하며 경로·계정이 불명확하면 시작하지 않는다. 각 기기 구현과 회귀 테스트를 확인한다.
3. 다중 대화 실행: 사용자가 검토해 시작한 계획을 서버의 개인 전용 상태 디렉터리에 저장한다. 브라우저 종료와 재접속 후 상태를 읽으며, 서버 중단 뒤 전송 중이던 건은 영수증으로 확인하고 불명인 경우 자동 중복 전송하지 않는다. 중지·재개·중복 요청·비정상 종료·busy 및 서로 다른 기기/폴더를 테스트한다. 새로운 승인 없는 작업 생성이나 권한 우회는 하지 않는다.
4. 통합: 기존 변경을 보존하고 프런트엔드·Python 전체/핵심 검사, 실제 CLI 격리 프로토콜 시험, 기기별 canary 및 배포 후 운영 readback을 진행한다. 실기기/계정별로 확인하지 못한 부분은 구분한다.
5. 코드 보관: 두 저장소의 개인 GitHub 계정과 실제 원격 상태를 확인한 뒤 변경 소유권·공개 범위·기존 커밋을 검토하고, 정확한 파일만 커밋·푸시한다. 기본 브랜치에 임의 병합하지 않는다. 기존 사용자 변경을 덮지 않는다.

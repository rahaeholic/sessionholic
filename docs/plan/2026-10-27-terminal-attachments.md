# 터미널 재연결과 첨부 복구

목표: 같은 Claude 대화가 작업 폴더를 옮겨도 기존 터미널·첨부를 계속 사용하고, 첨부 전송이 멎으면 취소·재시도로 돌아올 수 있게 한다.

1. `session_recovery.py`, `server.py`, `chat.py`, `web/app.js`: 기기·계정·확인된 대화 UUID로 같은 Claude 실행을 식별한다. 폴더 이동은 허용하되 다른 대화·계정, 추정 연결, Codex 폴더 경계는 유지한다. 기존 터미널 재사용과 메시지·첨부 경로를 함께 검증한다.
2. `chat.py`: 같은 Claude 대화의 이동 전 첨부는 서버가 보관한 출처로 검증한다. 새 업로드는 원본 기기가 확인한 현재 폴더에 저장한다. 다른 대화의 첨부와 임의 클라이언트 경로는 계속 거절한다.
3. `web/app.js`, `server.py`: 업로드에 기한·취소를 적용하고 실패 파일은 명시적인 재시도 또는 제거까지 남긴다. 보안 토큰 만료는 쓰기 전 거절된 경우에만 한 번 갱신한다. 원인별 오류를 보존하고 시작/종료 단계의 내용 없는 진단 로그로 전송 정체를 구분한다.
4. `prompt_receipts.py`의 질문 응답도 같은 대화 판정을 사용하되 기존 전달 기록과 중복 방지 서명은 유지한다. 기존 Python·프런트 테스트에 이동 후 재연결/전송, 이전 첨부, 타 세션 차단, 멎은 요청, 취소, 보안 토큰 갱신, 재시도를 추가한다. 관련 검증 후 전체 Python·JS 및 공개 파일 검사를 실행한다.
5. 검증된 커밋을 기존 배포 도구로 격리 사전 검증하고 운영에 반영한다. 제공 파일 해시, 기존 터미널 생존, 실제 사례의 연결 계획과 전송 가능 상태를 확인한다. 실제 사용자 대화에는 시험 메시지를 보내지 않는다.

새 모듈·의존성·설정은 추가하지 않는다. 운영 인증과 사용자 세션은 보존한다. 실제 휴대폰의 성공 여부와 모의 시험 결과는 구분해 보고한다.

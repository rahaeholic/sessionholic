# 터미널 본문과 작성창 통합

목표: 세션의 기본 작업 화면에서 실제 터미널과 하나의 하단 작성창으로 텍스트·음성·첨부·승인을 처리하고, 기록은 실행을 만들지 않는 별도 읽기 화면으로 제공한다.

사용자가 Codex의 기존 메시지 전송이 터미널에 나타남을 확인했으므로 이를 동작 전제로 삼는다. 이번 작업에서 실제 사용자 대화에 시험 입력이나 종료를 보내지 않는다.

파일 매핑:
- 수정: `web/app.js` — 작업/기록 보기, 확인된 기존 터미널 재사용, 안전한 기존 Chat.send 작성창, 승인·전송 상태, 새 세션의 미확인 직접 입력, 초안·음성 유지, 분할 창 복원과 포커스, 활성 창 크기 조정.
- 수정: `web/index.html`, `web/style.css`, `web/workspace.js`(필요 시), `web/workspace.css`(필요 시) — 기록/작업 명칭과 기본 화면, 터미널 아래 단일 작성창, 연결 전 안내, 좁은 화면과 각 분할 창의 배치.
- 수정: `tests/test_frontend.cjs`, `tests/test_workspace.cjs` — 전송 경로·영수증·초안·IME·음성·승인·기록·기존 연결 재사용·복원 경계의 회귀 검증.
- 수정: `README.md`, `docs/architecture.md`, `docs/limitations.md`, `scripts/public-files.json` — 새 동작과 검증 범위를 문서화.
- 참조만: `chat.py`, `native_chat.py`, `terminal.py`, `terminal_input.py`, 종료관리·복구 코드. 기존 ID·전송 영수증을 사용하며 새 DB·감시자·화면 파서는 만들지 않는다.
- 삭제 없음. 개인 리뷰·배포 증거는 `~/.codex-personal/discussions/`에 보관한다.

구현 순서와 검증:
1. 작업 보기와 기록 보기의 상태를 분리한다. 목록에서 선택하면 이미 살아 있는 정확한 터미널만 자동 표시한다. 연결이 없으면 원본 capability에 따른 작성창과 명시적 화면 연결 버튼을 보이고, 기록 선택·복원·갱신은 CLI를 시작하지 않는다. 일회성/봇/지운 기록은 기록 보기로 둔다. JS 검증: 기존 연결만 열기, 추정 연결 제외, 기록 조회에서 실행 API 없음.
2. 기존 Chat composer DOM을 터미널 아래에 그대로 유지한다. 정확히 연결된 작업은 Chat.send·업로드·영수증·승인 UI를 재사용하고 raw 작성창은 숨긴다. 미확인 새 세션은 명시적 터미널 직접 입력을 유지한다. 대상 불명 전송 금지, 결과 미확인 자동 재전송 없음, 전송 도중 고친 다음 초안 보존, IME·음성·첨부 갱신 중 입력 DOM 유지 등을 테스트한다.
3. 새 세션·분할 창에서도 같은 작업 화면과 포커스 규칙을 적용한다. 각 창의 기록 선택을 복원하고 키보드 이동은 보이는 작성창으로 간다. 다른 기기의 화면 크기를 백그라운드 창이 덮어쓰지 않도록 활성 입력/포커스에서만 서버 크기를 조정한다. JS 검증: 레이아웃/단일모드/숨은 창 복원·초안·마이크 객체 유지·키 충돌 없음.
4. 최종 변경을 리뷰하고 발견 사항을 수정한다. `node --test tests/test_*.cjs`, `python3 -m unittest discover -s tests -v`, `python3 scripts/check_public.py --release`, `git diff --check`를 통과시킨다. 가능한 승인된 브라우저로 화면을 확인하고, 도구 장애나 실제 하드웨어 미검증은 구분해 남긴다.
5. 기존 Mini 배포 도구로 한 번 배포한다. 설치 전후 기존 살아 있는 터미널 ID 유지, 설치 파일 해시·운영 응답·새 UI 자산을 확인한다. 배포 후 사용자 입력을 자동 발생시키지 않는다.

셀프 리뷰: UI와 전송 프로토콜을 분리해 기존 수신 확인과 종료관리를 보존한다. 기록은 원본 읽기 경로만 사용하고, native 대화와 터미널을 보편적인 1:1로 가정하지 않는다. 자동 연결은 기존 exact 터미널 표시까지만 허용한다. 기존 DOM을 유지해 네트워크 갱신이 작성·음성을 재생성하지 않게 한다.

구현 결정: 터미널 화면이 아직 연결되지 않아도 정확한 native route와 capability를 확인한 메시지는 기존 안전한 Chat.send로 보낼 수 있다. 새 터미널의 raw 작성창은 자동 교체하지 않고 명시적 버튼으로 전환한다. 따라서 목록/연결 갱신이 현재 IME·마이크·글자 선택을 끊지 않는다.

최종 리뷰 반영: 숨긴 세션의 답 필요 상태와 기록 보기의 알림을 작업 보기로 연결한다. 다른 창이 가진 터미널의 자동 동기화는 passive claim으로 포커스·토스트 없이 거절한다. 남은 raw 초안은 계속 보이며 통합 입력 이동 또는 양쪽 초안 보기/합치기를 명시적으로 선택할 수 있다. 기기·계정 이어가기와 실패 메시지 재시도 경로를 보존한다. 아직 준비되지 않은 분할 창의 알림 의도는 hook 준비 뒤 한 번 전달한다. 같은 raw 터미널의 자동 동기화는 IME를 blur하지 않는다.

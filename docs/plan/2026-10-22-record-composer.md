# 기록 탭에도 공통 작성창 유지

목표: 사용자가 기록 본문을 넓게 읽으면서도 작업 탭과 같은 하단 작성창에서 텍스트·음성·첨부·승인을 처리한다.

확인: 현재 CSS와 `renderDetailMode`가 기록 탭의 작성창·승인을 숨기고 `sendChat`·`renderPrompt`도 mode=chat을 거부한다. `chooseDetailMode`는 기록 전환 때 받아쓰기를 종료한다. 전송 자체는 이미 정확한 native source와 capability를 확인하는 공통 경로이므로 별도 터미널 입력 경로를 추가하지 않는다. 사용자 추가 요청은 터미널 스트림 복구 배포가 시작된 뒤 도착했으므로 해당 배포 확인 후 순차 반영한다.

파일 매핑:
- 수정: `web/app.js` — 기록에서도 기존 작성창·승인 표시 및 메시지 API 전송, 탭 전환의 IME·음성 유지, 재시도·알림이 기록에서 불필요하게 터미널 보기로 이동하지 않게 함, 창 이동 단축키의 작성창 포커스.
- 수정: `web/style.css` — 기록 전용 작성창·승인·모델 제어 숨김 제거. 기존 공통 하단 배치 사용.
- 수정: `tests/test_frontend.cjs` — 탭/복원의 무실행, 명시 전송의 같은 source·영수증·중복 잠금, 작성창·IME·마이크·첨부 동일성, 기록에서 승인·빠른 답장·실패 재시도·창 포커스, 일회성·봇의 입력 금지 보존.
- 수정: `README.md`, `docs/architecture.md`, `docs/limitations.md`, `scripts/public-files.json` — 양쪽 본문의 공통 작성창과 실제 지원 제한을 기록.
- 참조만: `chat.py`, `native_chat.py`, `server.py`, `web/workspace.js`, 종료·연결 판정. 삭제와 새 backend 전송 경로 없음.

순서와 검증:
1. 현재 기록의 숨김·전송 거부·탭 전환 음성 종료를 기존 fixture에서 재현한다.
2. 본문 보기와 전송을 분리하고 동일한 작성 DOM을 유지한다. native capability가 확인되지 않으면 초안만 허용하고 기존 연결/재개 절차를 유지한다. 일회성·봇은 작성창을 숨긴다. 단순 열기·복원이 CLI 시작이나 자동 전송을 만들지 않음을 검증한다.
3. 전체 JS 테스트, 공개 파일 감사, diff 검사 후 최종 리뷰한다. Mini 최신 운영 release를 기준으로 canary·원자적 배포·정적 해시·기존 터미널·제목 저장소·새 오류를 확인한다. 사용자 실제 대화 전송이나 마이크는 자동 실행하지 않는다.

셀프 리뷰: 기록 본문의 원본은 편집하지 않고 명시적 메시지만 같은 native 대화에 추가한다. 터미널 보기를 열지 않고도 기존 capability가 허용하는 전송을 사용한다. 승인 확인 단계와 중복 방지·결과 미확인 잠금을 보존한다. iPad 기본 탭이나 사용자가 저장한 보기 선택은 임의로 바꾸지 않는다.
